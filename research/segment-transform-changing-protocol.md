# Changing-work service screen

Retain64 recalls/four readers,16 future-dated writes,100ms/capacity16 shadow,
temporal reuse, persistent temporary LibraVDB and GOMAXPROCS4. Three rotated
off/direct/memo arm orders per workload. Workloads: four history groups (each
reader advances group every4 requests), and64 distinct histories. Request as-of
encodes fixture ID in microseconds solely for test dispatch; it is not evidence.

Each group changes an eligible final label/input. Precompute reference forecasts
outside timings; never feed those values into the candidate. Each successful
processor result must match its own reference within1e-12. Cache cold each arm.
Record fits, hits, verified returns, foreground timings and terminal statuses.

Screen per workload/trial: zero errors/full accounting/overlap, memo completed
>=52/64 and >=direct, memo p99<=1.10*off AND <=1.10*direct. All-distinct should
have zero hits regardless of performance; a false pass from cross-work reuse is
a correctness failure. Preserve failed cells; do not average away workloads.
Reference construction is excluded from measured service load. This is a
workload diagnostic, not live feedback learning or a real cache hit-rate model.
