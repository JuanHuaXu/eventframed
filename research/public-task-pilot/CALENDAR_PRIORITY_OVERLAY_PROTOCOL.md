# Post-correction temporal priority: service integration screen

This is a consumed-data engineering replay, not fresh confirmation or an MMM
learning claim. Use the frozen W3C, ESA written and ESA ISO fixtures. Two arms:
unchanged focus retrieval, and identical retrieval with the opt-in temporal
priority applied after numeric corrections and through priority-aware packing.
Both use diversity packing, recall50, pack1, budget10000, MaxRankDelta0.25.
No learned delta records are injected here; adversarial delta composition is a
separate component test. Both retain the same proper forecast machinery.

Run only with researchpriority and the generated priority-overlay-v1 overlay.
The ordinary runtime sources remain unchanged. Each query/arm has a fresh
memory store and uses the local embedding-only model. No answer generation,
private transcripts, OpenClaw, production persistence, or outcome updates.
Oracle files are read only after predictions. Existing data is already consumed.

Screen requirements, fixed before execution:

- All60 calls complete and source hashes verify.
- Every priority packet explanation equals its persisted journal explanation;
  snapshot and packed IDs match the returned packet.
- Opposite exclusions remain bound to distinct original questions, despite a
  shared retrieval focus. Direct service race tests exercise this independently.
- Proper laws are identical by event identity across both arms, for the entire
  frontier. Numeric ranker scores are unchanged and packed scores are original.
- Priority calibration is explicitly not_evaluated, with packet certainty0 as
  a legacy sentinel, not a probability or calibrated abstention score.
- Preserve every previously correct baseline case. Retain at least7/8 W3C,
  8/8 ESA written, and7/8 ISO positive top1 results. Absent-answer controls are
  reported separately; this mechanism does not implement abstention.
- Forced policy motion immediately before journal insertion retries rather
  than publishing a stale explanation. Disabled behavior is tested separately.

Recall wall times are diagnostic only, not loaded p99 or a performance gate.
Race tests and normal-build checks precede broader runtime adoption. Passing
this screen cannot close any of the seven whole research directions.
