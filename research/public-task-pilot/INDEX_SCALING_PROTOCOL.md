# Transaction index scaling diagnostic

Before running: compare HNSW(default) and flat collection indexes in unchanged
libravdb v1.6.13, synchronous durability, at200/800/1600 preexisting events.
For each, compare sixteen ordinary single writes against one16-event transaction.
Two fixed one-operation repetitions, CPU4. Twelve arms,24 observations. Fresh
DB per observation; seed using bounded transactions outside measured timing.

Primary measurement: time and allocation for sixteen writes. Separately report
mean search time for16 self-vector queries, top10 self-recall, and require durable
snapshot/payload verification after orderly reopen. Pseudo-random32-dimensional
vectors are generated by SHA256 of fixture IDs; they are not semantic embeddings.
All content is the same public Mars fact. No agent-task intelligence claim.

Hypothesis: default transactional HNSW write cost grows with corpus size more
strongly than flat's delta path. This is a finite diagnostic, not an asymptotic
proof, and flat still pays whole-corpus search costs. If flat improves writes,
do not substitute it for million-event retrieval without scaling/recall evidence.
Journal writes and concurrent arrivals are absent; do not claim service rescue.

Run no other agent-started tests/builds/benchmarks while this measurement runs.
Record raw stdout, exit status, timestamps and source hashes exclusively in
index-scaling-results.json. Preserve failures and do not rerun over that file.
