# Isolated worker-cap rescue screen

Frozen after the primary screen and its diagnostic profile, before this rescue
is measured. This is a consumed-design performance pilot, not scientific
confirmation, reference-implementation promotion or a whole-goal completion.

The pinned LibraVDB transaction code builds replacement affected-collection
indexes before commit. HNSW BatchInsert uses up to GOMAXPROCS concurrent workers.
The recorded profile is dominated by that construction and capture-released
read locks, not foreground input masks. Lowering process parallelism may reduce
construction/scheduler contention; it may also reduce throughput or make other
workloads slower. It does not remove the corpus-dependent rebuild cost.

Use unchanged repaired f3231fa control source, WITHOUT the mask candidate, and
the identical public-capture fixture. Compare explicit GOMAXPROCS=10 (this
host's logical CPU count) against GOMAXPROCS=2. Do not silently inherit a caller
environment setting. Both full frontiers 50 and 200 remain; two paired orders
are default/cap then cap/default. Fresh temporary stores in every command;
same 1,000 initial replicas, 256 future captures, 64 full recalls and 64 guarded
worker labels. No primary result is overwritten or replaced by this rescue.

Retain full samples and the unchanged absolute gates recall p99 <100 ms,
offered-to-observed live publication p99 <250 ms. Additional rescue screen:
cap/default recall p99 <=0.90 in BOTH repetitions at BOTH frontier sizes, with
all functional checks passing. Report capture count/bytes, overlap and init time
to expose a reduced-load or delayed-ingestion tradeoff. A serial writer's
closed-loop throughput changes with cap; this is not equal offered open-loop
load or a sustained overload guarantee. Do not use a passing result to claim
all CPU settings or million-record corpora fit the same latency envelope.

There is no source mutation, durability weakening, skipped scored candidate,
filter relaxation, session contamination or production setting change here.
Selection of two workers is an explicit post-diagnosis proposal, not retuning
after seeing its results. Negative cells remain negative.
