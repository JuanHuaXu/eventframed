# Local benchmark baseline: 2026-08-28

## Environment

- Base commit: `40f718e` plus the uncommitted benchmark harness
- Go: `go1.27.0 darwin/arm64`
- OS: macOS 26.6.2 (25G83)
- CPU: Apple M4
- Physical memory: 16 GiB
- Mode: sequential, warm in-process calls; no network embedding provider
- Recall contract: 384 dimensions, SQ8 traversal, `recall_k=50`, `pack_k=10`

Fixture construction was excluded from operation timers. Results include service
logic, LibraVDB access, Bayesian shadow evaluation and journaling, residual-cache
misses, reranking, and packing. Percentiles use Go's monotonic clock. They are
not concurrent daemon service-level percentiles.

Every timed recall advances `as_of` by one nanosecond. Eligibility therefore
stays fixed, while each operation receives a fresh decision-journal identity.
This measures ordinary turn processing rather than an idempotent retry.

## Recall and availability

| Case | Mean | p50 | p95 | p99 | Bytes/op | Allocs/op |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 events, all available | 7.643 ms | 7.971 ms | 8.982 ms | 9.043 ms | 1,736,033 | 5,227 |
| 1,000 events, 50% unavailable | 10.647 ms | 10.956 ms | 11.094 ms | 11.157 ms | 7,161,120 | 26,017 |
| 1,000 events, 95% unavailable | 14.612 ms | 14.948 ms | 15.101 ms | 15.240 ms | 11,626,055 | 45,230 |

The availability filter behaves correctly but probe expansion has a visible
allocation and latency cost. At 95% unavailable, p99 remains far below 100 ms on
this machine, while per-operation allocation is about seven times the normal
case. This is a priority target before concurrent load testing.

The normal 1,000-event case was rerun after the production default changed from
selective activation to complete bounded-frontier activation. Its p99 changed
from 9.026 ms to 9.043 ms, which is within single-run noise. No corpus-wide
posterior work was introduced.

The in-memory control backend showed the expected full-scan growth in the
calibration pass: 0.203 ms at 100 events, 0.667 ms at 1,000, and 5.991 ms at
10,000. These means are controls, not production-backend results.

## Agency active projection

Each operation claims ten records from a tenant-scoped active projection. A
zero-duration lease makes the same fixture eligible repeatedly; production uses
a 30-second lease.

| Active records | Mean | p50 | p95 | p99 | Bytes/op | Allocs/op |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 5.312 ms | 5.166 ms | 6.087 ms | 6.350 ms | 90,714 | 623 |
| 100 | 5.783 ms | 5.962 ms | 6.998 ms | 7.269 ms | 980,647 | 3,717 |
| 1,000 | 8.858 ms | 8.983 ms | 9.108 ms | 9.210 ms | 8,732,491 | 29,701 |

The bounded projection removes dependence on lifetime proposal history. The
1,000-record ceiling remains below 10 ms p99 sequentially, but its 8.7 MiB per
claim allocation can create garbage-collection pressure under frequent or
concurrent polling.

## Whole-process memory

Using `/usr/bin/time -l` around a precompiled benchmark executable:

- 1,000-event normal SQ8 recall: 115,507,200-byte maximum resident set size
  (about 110.2 MiB).
- 1,000-record agency claim: 100,302,848-byte maximum resident set size
  (about 95.7 MiB).

These figures include the Go runtime, benchmark fixture, LibraVDB, indexes, and
test harness. They are process peaks, not incremental memory per request.

## Findings and limits

1. The measured local paths support the sub-100 ms design target at 1,000
   records, including severe availability filtering and the maximum agency queue.
2. Allocation volume is the first clear performance concern. Tail latency under
   concurrent calls may differ materially from these sequential results.
3. Constructing the 10,000-event durable SQ8 fixture through one transaction per
   observation exceeded 209 seconds before the calibration run was stopped. No
   10,000-event LibraVDB recall number is claimed. Index-build and batch-ingestion
   performance require a separate benchmark and likely a reusable persisted
   fixture.
4. The run excludes Unix-socket HTTP, OpenClaw adapter work, external embedding
   latency, mixed reads and writes, cold restart, and concurrent tenants.
5. Accuracy, calibration, omitted-influence coverage, false Anti-Pigeon merges,
   and comparisons with update-all and naive-selective baselines remain required
   before production claims.

## Reproduction

```sh
go test ./benchmark -run '^$' -bench . -benchmem -benchtime=1s -count=5
EVENTFRAME_BENCH_LARGE=1 go test ./benchmark -run '^$' -bench '^BenchmarkAgencyClaim/' -benchmem -benchtime=2s -count=1
```
