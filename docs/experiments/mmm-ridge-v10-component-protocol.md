# Ridge specialist on consumed v10 observation tapes

Frozen 2026-10-01 after the v10 failure and issued-expert diagnostic. This
is a component feasibility screen on **already consumed** synthetic data.
It cannot confirm a selected rescue, justify production adoption, or replace
the original v10 verdict. The research-only ridge fitter previously failed
a broad standalone test; that negative result remains active.

Read both complete v10 journals, all ten scenarios, both original phases,
all three fit groups and eight streams each (960 streams total). Reconstruct
each online input and outcome from the archived role-0 seed; reject any
mismatch. At clock t, issue a specialist prediction using only a ridge law
published after earlier delivered paid audits. Never use the current or a
future outcome, regenerate a past forecast with a later model, or use a
teacher law. For each of the four archived observation arms, forecast on
that arm's actual final mask/value only; verify it agrees with the
reconstructed input.

On each delivered audit, append its original full input and outcome. Keep
the last 64 delivered audit samples. After at least 32 audits, refit at
every 16th delivered audit, matching the current learner cadence. Fit the
existing `fitRidgeLogistic` with its frozen unit ridge penalty and 32-step
solver cap; compile `conditional` with **uniform fixed input weights**.
No true input-generator mass, scenario identity, true change time, oracle
label or group name may enter this fit or forecast. The uniform completion
is intentionally also tested under the latent-correlated input mode.
If fitting or compilation fails, record the failure and keep the previously
published law; if none exists, use the corresponding archived incumbent.
Never discard a trajectory because of a solver failure.

Before the first completed fit, the candidate returns the corresponding
archived issued final forecast. Thereafter it returns the ridge conditional
forecast. Also report ridge-only and incumbent loss on identical ready
frames, so fallback does not hide poor capacity. Record every fit failure,
publication count, sample origin, forecast, score and timing. Do not drop
failed trajectories. Compare candidate+fallback with the archived incumbent
over every scenario/window, retaining stable, null, interaction, recurring,
delayed/missing and both primary shifts. For diagnosis, reuse the v8 primary
gain >=0.005 with positive 3.6-SE lower bound and fit-group signs,
stationary protection and -0.01 mean-harm floor; these are NOT fresh
confirmation gates on this consumed corpus.

Audit exact as-of delivery ordering, per-frame mask consistency, source
hashes, independent score recomputation and fit/compile/forecast cost.
Subsequent integration would need a separate admission rule, proper-score
noninferiority, new outcome families, unseen agent tasks and loaded latency.
